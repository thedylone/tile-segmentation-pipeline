Segmentation Pipeline for 3D Tiles

A proof of concept, built during my DSTA internship in 2023, that labels the polygons of the glTF models inside a 3D Tileset. It segments each model's 2D textures with a Transformer and maps those labels back onto the mesh through its texture coordinates.

01 — Overview

Why segment textures

Rather than segmenting the 3D geometry itself, the pipeline segments the texture images each model already carries, using a pretrained 2D segmentation model, and lets the glTF's own UV mapping carry the result into 3D.

The model is facebook/mask2former-swin-small-cityscapes-semantic, loaded with Hugging Face Transformers. For each vertex, the texture coordinate (0–1 in both axes) is scaled to the mask's size, and the class at that pixel becomes the vertex's class. Classes follow the model's Cityscapes label set: building is class 2 and vegetation is class 8.

The full write-up is on D-Classified on Medium.

02 — Method

From a tileset to labelled geometry

pipeline.py walks the tileset, segments every model it finds, and writes the result back out as a tileset with per-vertex class metadata.

  1. Step 01

    3D Tileset

    Traverse tileset.json and its child tilesets to find every tile's content.

  2. Step 02

    glTF / glb

    Load each .glb, decompressing Draco-compressed meshes with DracoPy.

  3. Step 03

    Texture extraction

    Pull the embedded texture images out of the glTF buffers as Pillow images.

  4. Step 04

    2D semantic segmentation

    Mask2Former (Swin-S, Cityscapes) predicts a class for every texture pixel.

  5. Step 05

    UV → polygon back-projection

    Each vertex's texture coordinate looks up its pixel in the mask; polygons take their vertices' class.

  6. Step 06

    Labelled 3D output

    Write the classes as glb metadata, or split polygons by class into a new tileset.

04 — Usage

Two outputs, at tileset scale

Output A · metadata

Each segmented .glb gets an EXT_mesh_features feature-ID attribute (_FEATURE_ID_0) holding every vertex's class. The bundled CesiumJS viewer reads it with a custom shader to colour the classes.

Output B · --submeshes

Polygons are grouped by class into separate .glb files, and py3dtiles converts them into a new 3D Tileset that carries the class labels.

Large tilesets take a long time to process, so extract_tileset.py can cut out a single branch first. You can select it by a target file name or a latitude/longitude bounding box, and keep the neighbouring tiles if you need them. The pipeline also resumes after an interruption by skipping tiles whose output already exists. 

# segment a tileset, writing labelled .glb files
python pipeline.py --file tileset.json --input input/ --output output/

# or split by class into a new tileset
python pipeline.py --file tileset.json --input input/ --output output/ --submeshes
